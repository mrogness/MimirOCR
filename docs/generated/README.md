# Generated documentation

Edit source models/comments or the owning generator, then regenerate. Do not
hand-edit derived files, including when changing generator logic.

| Output | Generated by | When | Committed? |
| --- | --- | --- | --- |
| HTTP Markdown/JSON and approximate test inventory in `docs/generated/` | `scripts/generate_docs.py` | `yarn docs:generate` | Yes; CI checks for drift |
| Python/JavaScript/Vue source reference and navigation | `scripts/generate_reference.py`, `scripts/docs/` | `yarn docs:build` or `yarn docs:serve` | No |
| Worker exchange examples page | `scripts/docs/reference.py`, from the JSON fixture | Docs build/serve | No; source fixture is committed |
| Build version/revision labels and `reference/build.json` | `scripts/docs/build_info.py` | Docs build/serve | No |

See [documentation automation](../maintenance/automation.md) for setup and CI.
Worker fixtures are validated against production protocol/domain models during
`docs:generate`. Source comments are extracted during builds; rendered pages are
not the place to edit descriptions. Architecture, guides, and tutorials remain
manually maintained.
